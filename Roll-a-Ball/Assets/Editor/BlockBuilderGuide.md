# Block Builder

Scene View で Prefab をグリッド配置する Editor 専用ツール。Unity 6000.3.20f1 用。
主要機能は `BlockBuilderWindow.cs` にあり、ゲーム実行用の MonoBehaviour は追加しない。

## 開始方法

1. Play モードを停止し、Prefab Mode ではないシーンを開く。
2. `Tools > Block Builder` を開く。
3. グリッド幅（初期値 1）、チャンク幅（初期値 16）を指定し、「専用ルートを新規作成」を押す。
4. スロット 1〜9 に Prefab をドラッグ＆ドロップする。
5. Scene View または Block Builder ウィンドウで B を押して FPS 配置モードへ入る。

既存ルートを編集するときは「配置ルート」欄へ Hierarchy のオブジェクトを指定する。ルート名は自由で、`Stage` の子に置いたり、移動・回転・拡縮しても編集できる。グリッドは配置ルートのローカル座標を基準にする（Scale 0 は使用不可）。

初めて指定したルートには設定用の子 `__BlockBuilderSettings_v1|...` を追加する。設定のない任意のオブジェクトはウィンドウの新規ルート設定を採用し、旧形式の名前が残るルートは従来の値を引き継ぐ。以後はルート名を変えても設定を保持し、設定用の子を含めて Prefab 化すれば設定も引き継ぐ。新規ルート用の設定は設定済みのルートには適用されない。Prefab アセット自体ではなく Scene 上のインスタンスを配置ルートに指定する。

スロット登録は EditorPrefs に保存され、同じプロジェクト・ユーザーで再起動後も復元される。配置したシーンデータは通常どおりシーンを保存する。

## FPS 配置モード

| 入力 | 動作 |
| --- | --- |
| B / Esc | モード終了 |
| マウス移動 | 一人称視点の回転 |
| WASD | 水平移動 |
| Q / E | ワールド Y 軸に沿って上昇 / 下降（カメラの向きに依存しない） |
| 1〜9 / ホイール | ホットバー切替 |
| 右クリック | 候補セルへ配置 |
| 右クリック長押し | 初期値 0.45 秒間隔で連続配置 |
| 左クリック | 照準下の管理対象ブロックを破壊 |

移動速度の初期値は 10 セル / 秒。Scene View と Block Builder ウィンドウに現在のモードを表示する。Windows Editor では配置モード中に実カーソルを非表示にして中央の照準を使い、終了・フォーカス喪失時に表示と移動制限を復元する。開始は Scene View の描画タイミングまで予約し、カーソル捕捉と照準の座標系を揃える。モード終了時には開始前の Scene View の視点・投影・FOV 等も復元する。WASD / QE は編集用移動で、歩行・重力・衝突処理はない。

## Collider のチャンク化（選択して確定）

Collider の一括統合は、対象を確認してから実行する明示的な手順になっている。

1. Block Builder の「Collider チャンク化（選択式）」を開き、「選択されたブロックをまとめてチャンク化する」を押す。
2. Scene View でブロックをクリックして選択する。選択中は緑の枠、カーソル下は水色の枠で表示する。再クリックで選択解除できる。Unity の Hierarchy 選択状態は変更しない。
3. 選択数と統合不可ブロック数を確認し、Block Builder ウィンドウに戻って「選択を確定してチャンク化」を押す。
4. 内容を戻す場合は Undo を実行する。選択をやり直すときは「選択をクリア」または「選択をキャンセル」を使う。Scene View の Esc でもキャンセルできる。

選択した管理ブロックだけの表示メッシュから、物理判定用のメッシュを生成し、1つの MeshCollider（Convex オフ）にまとめる。斜面・凹凸・隙間をセルの箱に置き換えず保持する。描画用の Prefab、Renderer、元メッシュは変更せず、元のブロックは個別編集できるまま残す。生成した物理メッシュはシーンに保存されるため、実行時に Editor ツールは必要ない。

- 固定ステージ用。Trigger・Rigidbody（親を含む）・SkinnedMeshRenderer を含む対象は統合しない。移動する物体やアニメーションする形状には使用しない。
- 有効な MeshRenderer と MeshFilter が必要。Read/Write 無効の FBX も Importer を変更せず読み取る。LODGroup は LOD0 を使用する。
- 同じ Layer のブロックを選択する。子 MeshRenderer もブロックと同じ Layer に揃える。統合後もこの Layer を保持する。
- 物理マテリアルは既定値を使用する。テクスチャの透明部分やシェーダーによる変形は形状に反映しない。面の裏側や開いたメッシュは、元メッシュの面方向に従う。
- 表示メッシュの三角形を使うため、単純な BoxCollider より負荷が高くなる場合がある。結合は面同士を削除するブーリアン演算ではない。
- 過去に作成したセル形状の BoxCollider グループは自動変換しない。対象を選び直して「選択を確定してチャンク化」を押すと新方式へ切り替わる。

ルート直下に置かれた Block Builder 管理ブロック以外は選択対象にならない。

### チャンク解除

- 選択済みブロックを個別 Collider に戻すには、同じ選択モードで対象を選び「選択したブロックを個別 Collider に戻す」を押す。複数ブロックのグループから一部だけ解除した場合、残りのブロックの Collider は再生成される。
- 新規ルートは全体自動統合を行わない。統合失敗時は古い派生 Collider を残さず、元の Collider を有効にして物理判定を維持する。
- チャンクの追加・削除・Undo/Redo・シーン再読込では、変更が必要な Collider だけを同期する。グループ操作は Undo 一回で戻せる。

## 配置・保存形式

- Scene View 中央の照準が操作位置。設定可能な色の枠が次の配置セル、黄色い枠が照準下の既存ブロック。
- Renderer 範囲を優先し、Renderer がない場合は Collider 範囲を使う。ブロック以外を破壊しない。
- 最初の足場がない場合は配置ルートのローカル Y=0 の仮想平面へ配置でき、到達距離は 128 セル。
- Prefab は縦横比を保ってセルに合わせる設定があり、重複セルや 4096 セルを超えるブロックは配置できない。
- 連続配置一回は Undo 一回で取り消せる。
- ウィンドウには配置範囲、ブロック数、照準セル、チャンク座標を表示する。「選択チャンク（X / Z）」または「照準のチャンクを選択」でチャンク境界を表示する。

実行時スクリプトを追加せず、設定用の子と管理対象の標準 GameObject に管理情報を保存する。配置ルート自身の名前は識別に使わない。

- `__BlockBuilderSettings_v1|グリッド幅|チャンク幅|統合フラグ`：ルート直下の設定用オブジェクト
- `ルート名_Prefab名|BB1|配置時の各 Collider 有効フラグ|Prefab 名`：新規配置ブロック
- `ルート名_Collider|BBChunk|Group|識別子`：新規生成 Collider
- `BlockBuilder_v1|グリッド幅|チャンク幅|統合フラグ` と `BB1|...`：互換性のため読み込める旧形式
- `BB1|...|Group=識別子`：手動 Collider グループに所属するブロック
- `BB1|...|Group=Mesh-識別子`：表示メッシュに沿う MeshCollider グループのブロック
- `BBMesh|形状ハッシュ`：シーンに保存する生成済み物理メッシュ
- `BB1|...|Group=`：明示的に個別 Collider に戻したブロック
- `BBChunk|Group|識別子`：手動グループの派生 Collider
- `BBChunk|X|Z`：旧全体自動統合の派生 Collider

生成時の表示名には配置ルート名を使う。ルート改名後も既存ブロックを識別でき、以後生成するブロック・Colliderには新しいルート名を使う。設定用オブジェクトとブロック名末尾の管理部分は編集せず、管理ブロックはルート直下に置く。Collider の構成・有効状態を編集する場合は、先に該当グループを個別 Collider に戻す。

## 手動確認手順

1. Prefab を複数配置し、新規ルートでは元 Collider が維持されることを確認する。
2. チャンク化を開始し、Scene View でクリックした対象のみ緑枠になること、再クリックで解除できること、Hierarchy の選択が変わらないことを確認する。
3. 統合不可ブロックを含む選択では確定ボタンが無効になり、統合可能な対象だけなら有効になることを確認する。
4. 確定後、選択したブロックの元 Collider が無効、生成された `BBChunk|Group|Mesh-...` の MeshCollider が有効かつ Convex オフになることを確認する。斜面や離れたブロックの隙間も形状どおり判定されること、未選択ブロックは変化しないことを確認する。
5. Undo / Redo でグループ、元 Collider、派生 Collider が整合することを確認する。
6. グループの一部を選んで個別 Collider に戻し、残りのグループが再構築されることを確認する。
7. B キーで配置モードが維持され、実カーソルが非表示になることを確認する。B / Esc とフォーカス喪失で表示と移動制限が復元されることを確認する。
8. 外部オブジェクトやチャンク Collider が選択・破壊対象にならないこと、Alt の Scene View 操作が使えることを確認する。
9. Scene 保存・再読込後もグループが維持され、変更されたチャンクだけが同期されることを確認する。
10. ルートの改名、親の追加、移動・回転・拡縮後も同じローカルセルへ配置できること、Prefab 化した別インスタンスでも設定と既存ブロックが認識されることを確認する。

実装後の Unity Editor 上での動作確認結果は、作業報告でコンパイル確認と分けて記載する。
