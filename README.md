## 🌿 Git ブランチ運用ルール

当プロジェクトでは、安全にチームでコードやアセットを共有するために**ブランチ運用**を行います。

### 基本ルール
* **作業は必ず `master` ブランチから作成した `feature` ブランチで行います。**
* `master` ブランチに直接変更をコミット・Push することは禁止です。
* `master` ブランチに merge する前に、必ず PR を展開して、見てもらいましょう！

---

## 🔰 初心者向け Git & ブランチ解説

### Q. 「ブランチ（Branch）」ってなに？
ブランチ（枝）とは、**メインの作業場所（`master`）から自分専用の作業コピーを作成して作業する仕組み**です。  
自分専用の部屋（`feature/〇〇`）で作業するため、作業中に失敗したり試行錯誤しても、他の人の作業や動くゲーム（`master`）を壊す心配がありません。

### 🔄 基本の開発ワークフロー

1. **最新の `master` を取得する**
   * 作業を始める前に、必ず `master` ブランチを最新状態（Pull）に更新します。
2. **作業用ブランチを作成する**
   * `master` から新しいブランチを作成します。
   * **ブランチ名の命名規則**: `feature/担当内容`
     * 例: `feature/player-movement`（プレイヤー移動処理）
     * 例: `feature/stage1-model`（ステージ1の3Dモデル）
3. **作業をしてコミット＆Pushする**
   * キリの良いタイミングで変更をコミットし、自分のブランチを GitHub へ Push します。
4. **プルリクエスト（Pull Request / PR）を作成する**
   * 作業が完了したら、GitHub 上で「`feature/〇〇` の変更を `master` に合流させてください」という申請（プルリクエスト）を送ります。
   * PR を作成したら、レビュワーに作ったことを知らせるため、Discord でアピールしましょう！
5. **レビュー & 合流（Merge）**
   * チームメンバーの確認後、`master` に変更が合流されます。
